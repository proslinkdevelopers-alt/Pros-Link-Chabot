# API reference — Pros-Link platform

All endpoints return JSON unless noted. Console endpoints answer
`{ ok: true, ... }` on success and `{ error, fields? }` on failure, where
`fields` maps a form field to what is wrong with it.

---

## Public endpoints

### `POST /api/chat` — one turn with the web assistant

```json
{
  "conversationRef": "PL-CONV-7F3K2Q9ABC",
  "input": { "kind": "text", "text": "Do you have digital duplicators?" }
}
```

`conversationRef` is generated by the browser (`PL-CONV-` + 10 characters from
`A–Z` minus `I`/`O` and `2–9`) and identifies the thread; the first message
creates it. A tap is `{ "kind": "reply", "text": "<title>", "replyId": "<id>" }`
using an id from a previous response.

Response:

```json
{
  "reference": "PL-CONV-7F3K2Q9ABC",
  "language": "en",
  "messages": [{ "type": "list", "body": "…", "button": "View options", "rows": [{ "id": "n:products", "title": "Products" }] }],
  "records": [{ "kind": "QUOTE", "reference": "PL-QTE-9GCU9RFJ" }],
  "staffHandling": false
}
```

`messages[]` are `text`, `buttons` or `list` items. `records` lists what this
turn created (lead, quote, ticket, appointment). Rate limit: 30 turns a minute
per IP (`429`).

### `GET /api/chat/messages?ref=<conversationRef>&after=<ISO time>`

Replies written by staff in the console after `after`, for a website thread:
`{ "replies": [{ "id", "body", "at" }] }`. Only the holder of the random
reference can read them. Rate limit: 40 a minute per IP.

### `GET /api/catalog`

- no parameters → `{ categories: [{ slug, name, description, icon, productCount }], brands: ["…"] }`
  (active categories; verified and active brands only)
- `?category=<slug>` → `{ category, count, products: [...] }` (published products)
- `?product=<id or slug>` → `{ product }` or `404`

A product carries `name, slug, sku, model, summary, description, images,
features, specifications [{label,value}], documents [{title,url}],
availability, category, brand (null unless verified), keywords`.

### `GET /api/search?q=<text>&limit=<1-25>`

Published knowledge entries matching the query:
`{ query, count, results: [{ id, category, question, answer }] }`.

### `POST /api/leads` — website enquiry or quote form

```json
{
  "name": "Sara Khan", "company": "Nova Traders", "phone": "0300 1234567",
  "whatsapp": "", "email": "", "city": "Lahore",
  "category": "photocopiers-mfps", "productId": null,
  "quantity": "2", "budget": "", "preferredContact": "WhatsApp",
  "requirements": "A3 colour copier for the accounts department",
  "quote": true
}
```

Creates a lead (stage `QUOTE_REQUESTED` when `quote` is true, plus a quote
request), links the customer profile, notifies staff. Returns
`201 { ok, reference, message }`. Rate limit: 5 per 10 minutes per IP.

### `POST /api/tickets` — website service request form

```json
{
  "category": "REPAIR", "name": "Bilal Ahmed", "company": "", "phone": "0321 7654321",
  "email": "", "city": "Multan", "address": "",
  "machineType": "Photocopier", "machineBrand": "", "machineModel": "", "serialNumber": "",
  "urgent": true, "description": "Paper jams on every page",
  "preferredDate": "2026-09-25", "preferredTime": "Morning"
}
```

`category`: `INSTALLATION | TECHNICAL | MAINTENANCE | REPAIR | SERVICE | PARTS |
COMPLAINT | CALLBACK | GENERAL`. Returns `201 { ok, reference, message }`.
Rate limit: 6 per 10 minutes per IP.

### `GET /api/health`

`{ status: "healthy" | "degraded", checks: { app, database, redis }, provider, model, timestamp }` —
`503` when the database is unreachable.

### WhatsApp webhook — `GET|POST /webhook` (alias of `/api/whatsapp/webhook`)

- `GET` — Meta's verification: echoes `hub.challenge` when `hub.verify_token`
  equals `WHATSAPP_VERIFY_TOKEN`, otherwise `403`.
- `POST` — message and status deliveries. Refused with `401` unless
  `X-Hub-Signature-256` matches the raw body signed with `WHATSAPP_APP_SECRET`.
  Always `200` once verified (Meta retries on anything else); retries of the
  same message id are ignored.

### `GET /api/cron/follow-ups`

Sends due WhatsApp follow-ups. Requires `Authorization: Bearer $CRON_SECRET`
(`503` when the secret or WhatsApp is not configured, `401` when wrong).

### Authentication

| Endpoint | Body | Result |
| --- | --- | --- |
| `POST /api/auth/login` | `{ email, password }` | `200` + HttpOnly `pl_session` cookie · `401` (one generic message) · `429` throttled |
| `POST /api/auth/logout` | — | Clears the cookie |

There is no public registration; staff accounts are created in Admin ▸ Team.

## Console endpoints

All require a signed-in staff session. State-changing requests must be
same-origin. The permission named is checked on the server before anything is
read; `403` otherwise. Records are always looked up within the Pros-Link tenant
(`404` for anything else).

| Method & path | Permission | Purpose |
| --- | --- | --- |
| `GET /api/admin/search?q=` | any staff | Records the role may see, for Ctrl+K |
| `PATCH /api/admin/leads/:id` | `leads.manage` | Stage, priority, owner, value, next step, details |
| `POST /api/admin/leads` | `leads.manage` | Add a lead |
| `PATCH /api/admin/customers/:id` | `customers.manage` | Status, owner, details |
| `POST /api/admin/customers` | `customers.manage` | Add a customer (`409 { existingId }` if the phone/email is on file) |
| `POST /api/admin/assets` · `PATCH/DELETE /api/admin/assets/:id` | `customers.manage` | Machines at a customer's site |
| `PATCH /api/admin/tickets/:id` | `tickets.manage` (technician: own ticket, status + resolution only) | Status, priority, assignee, details |
| `POST /api/admin/tickets` | `tickets.manage` | Raise a ticket |
| `PATCH /api/admin/quotes/:id` | `quotes.manage` | Status, owner, line items, discount, tax, terms (totals computed server-side) |
| `POST /api/admin/quotes` | `quotes.manage` | Start a quotation from a lead `{ leadId }` |
| `PATCH /api/admin/meetings/:id` | `appointments.manage` | Status, host, time, mode, notes |
| `POST /api/admin/activities` | manage permission of the record | Note, call, follow-up on a lead, customer, ticket, quote or conversation |
| `PATCH /api/admin/activities/:id` | owner of the follow-up | Mark done |
| `PATCH /api/admin/conversations/:id` | `conversations.reply` (pause/read) · `conversations.manage` (assign, tag, close) | Work a thread |
| `POST /api/admin/conversations/:id/reply` | `conversations.reply` | Reply on WhatsApp (24-hour window) or the website |
| `POST /api/admin/conversations/:id/convert` | `leads.manage` / `quotes.manage` / `tickets.manage` | `{ kind: "LEAD" | "QUOTE" | "TICKET", category? }` |
| `POST /api/admin/products` · `PATCH/DELETE /api/admin/products/:id` | `products.manage` | Catalogue (delete refused while referenced) |
| `POST /api/admin/categories` · `PATCH/DELETE …/:id` | `products.manage` | Categories |
| `POST /api/admin/brands` · `PATCH/DELETE …/:id` | `products.manage` | Brands (verified + active to be public) |
| `POST /api/admin/knowledge` · `PATCH/DELETE …/:id` | `knowledge.manage` | Knowledge base |
| `PUT` · `DELETE /api/admin/bot-config/:section` | `chatbot.manage` | Save a Chatbot Studio section, or reset it to the default |
| `POST /api/admin/bot/simulate` | `chatbot.manage` | Simulator turn (nothing sent or saved) |
| `POST /api/admin/team` · `PATCH /api/admin/team/:id` | `team.manage` | Staff accounts, roles, activation, password reset |
| `PUT /api/admin/settings/company` | `settings.manage` | Company profile |
| `PATCH /api/admin/notifications` | `notifications.view` | Mark own notifications read `{ ids }` or `{ all: true }` |
| `GET /api/admin/reports/export?type=leads|tickets&days=7|30|90` | `reports.view` + view permission | CSV (audited) |
| `GET /api/admin/whatsapp/media/:id` | may see the conversation or ticket | Relay a customer photo/document from Meta |
| `…/api/admin/templates*`, `…/api/admin/broadcasts*` | `whatsapp.manage` | Templates and broadcasts |

Every successful change is written to the audit log with the previous and new
value of each field.
